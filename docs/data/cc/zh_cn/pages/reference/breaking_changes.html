版本之间的不兼容性

CC：Tweaked 尝试尽可能保持版本之间的兼容性，这意味着为旧版本 模组 编写的大多数程序应该在更高版本上运行良好。

⚠ 外设

虽然《CC：调整》在各个版本中相对稳定，但对于添加自己的外设的其他模组来说可能并非如此。与外部块交互的旧程序可能无法在较新版本的游戏上运行。

然而，对底层游戏或《CC：Tweaked》自身内部结构的一些更改可能会破坏某些程序。此页面作为重大更改的文档，以及版本之间应注意的“陷阱”。

CC：将 1.109.0 调整为 1.109.3

  • 更新至 Lua 5.2:

    • 对 Lua 5.0 伪参数 arg 的支持已被删除。您应该始终使用 ... 作为可变参数。
    • 环境不再烘焙到运行时中，而是使用 _ENV 本地或上值。 getfenv/setfenv 现在仅适用于具有 _ENV 上值的 Lua 函数。 getfenv 与其他函数一起调用时将返回全局环境，而 setfenv 将不起作用。
    • load/loadstring 默认使用全局环境（_G）而不是当前协程的环境。
    • 已删除对转储函数 (string.dump) 和加载二进制块的支持。
    • math.random 现在使用 Lua 5.4 的随机数生成器。

  • 文件句柄、HTTP 请求和 Websocket 现在始终使用原始字节，而不是编码/解码为 UTF-8。如果使用文本模式，包含非 ASCII 字符的文件将以不同的方式读回。

我的世界 1.13

  • 由于 Minecraft 更新到 LWJGL 3，key 和 key_up 事件的“关键代码”已更改。请确保您使用 keys API 提供的常量，而不是硬编码数值。

    与此更改相关，数字键盘回车键现在具有与回车键不同的键码。您可能需要调整您的程序来处理这两者。 （注意，keys.numpadEnter常量是在CC 1.13之前的版本中定义的，但keys.enter常量在按键时排队）

  • Minecraft 1.13 删除了物品损坏和块元数据的概念（请参阅“扁平化”）。因此，turtle.inspect 不再提供块元数据，并且 turtle.getItemDetail 不再提供损坏。

    • 块状态（turtle.inspect().state）应提供与块元数据相同的信息，但采用更易于理解的格式。

    • 物品和方块名称现在代表唯一的物品类型。例如，羊毛被分成 16 个单独的项目（minecraft:white_wool 等），而不是单个 minecraft:wool，每个元/损坏值指定颜色。

  • 自定义 ROM 现在使用数据包而不是资源包提供。这应该主要是将“assets”文件夹重命名为“data”，并将其放入“datapacks”中，但还有一些其他问题需要注意：

    • 数据包对文件名施加了一些限制。因此，您的程序和目录必须全部小写。
    • 由于 CC 读取数据包的方式：调整，您可能需要使用 /reload 命令来查看计算机上显示的数据包更改。

    有关更多信息，请参阅数据包。

  • 海龟现在可以在浸水的情况下“穿过”水源，而不是破坏水源。

CC：调整1.88.0

  • 未标记的计算机和海龟现在在损坏时会保留其 ID，这意味着未标记的计算机/物品不会堆叠。

计算机工艺 1.80pr1

  • 通过shell.run运行的程序现在在它们自己的隔离环境中启动。这意味着程序设置的全局变量将无法在该程序之外访问。

  • 包含/的程序在当前目录中查找，不再在路径上查找。例如，您不能再输入 turtle/excavate 来运行 /rom/programs/turtle/excavate.lua.
