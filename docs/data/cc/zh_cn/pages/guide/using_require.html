通过 require 重用代码

库是有用函数和其他定义的集合，它们单独存储到主程序中。您可能想要创建一个库，因为您有一些在多个程序中使用的函数，或者只是将您的程序拆分为多个更模块化的文件。

假设我们想要创建一个小型库，以便更轻松地使用 终端 。我们将提供两个函数：reset，它清除终端并将光标设置为 (1, 1)，以及 write_center，它在屏幕中间打印一些文本。

首先创建一个名为 more_term.lua 的文件：

local function reset()
  term.clear()
  term.setCursorPos(1, 1)
end

local function write_center(text)
  local x, y = term.getCursorPos()
  local width, height = term.getSize()
  term.setCursorPos(math.floor((width - #text) / 2) + 1, y)
  term.write(text)
end

return { reset = reset, write_center = write_center }

现在，这是怎么回事？我们按照预期定义了两个函数，然后在底部返回一个包含这两个函数的表。当我们需要这个库时，就会返回这个表。这样，我们就可以调用原始函数了。现在创建一个新文件，其中包含以下内容：

local more_term = require("more_term")
more_term.reset()
more_term.write_center("Hello, world!")

运行时，这将清除屏幕并在第一行中间打印一些文本。

要求深入

虽然上一节很好地介绍了 require 的操作方式，但对于更高级的用法，还有一些剩余的要点值得一提。

图书馆可以返回任何东西

在上面的示例中，我们返回一个包含我们要公开的函数的表。然而，值得指出的是，您可以从库中返回“任何内容”——表、函数甚至只是一个字符串！ require 对它们一视同仁，只返回你的库提供的任何内容。

模块解析和包路径

在上面的示例中，我们在文件中定义了库，并 require 从中读取。虽然这是您大多数时间都会做的事情，但可以使 require 在其他地方查找您的库，例如从网站下载或从内存中的库存储加载。

因此，模块名（传给 require）并不对应文件路径。一个常见错误是用 require("folder/library") 甚至 require("folder/library.lua") 从子目录加载代码，这两者都不会完全按预期工作。

从文件加载库（也称为 模块）时，require 沿着 模块路径搜索。默认情况下，这看起来像：

  • ?.lua
  • ?/init.lua
  • /rom/modules/main/?.lua
  • ETC...

调用 require("my_library") 时，require 会把路径中每个元素的 ? 替换为你的模块名，并检查文件是否存在。这里我们会查找 my_library.lua、my_library/init.lua、/rom/modules/main/my_library.lua 等。注意这相对于当前程序工作，所以如果你的程序实际名为 folder/program，我们就会查找 folder/my_library.lua，等等……

另一个需要注意的是从子目录加载库。例如，假设我们有一个文件 my/fancy/library.lua。可以使用 require("my.fancy.library") 加载它 - 在我们开始查找库之前，将“.”替换为“/”。
