使用扬声器播放音频

CC：Tweaked 的扬声器外设提供了一种强大的方式，可以使用 speaker.playAudio 方法播放您喜欢的任何音频。然而，对于不熟悉数字音频的人来说，这并不是最直观的使用方式。本指南介绍了数字音频，演示了如何使用 CC: Tweaked 的扬声器播放音乐，然后简要讨论了更复杂的音频处理主题。

数字音频简介

当声音被记录时，它被捕获为模拟信号，实际上是声波的电子版本。然而，该信号是连续的，因此不能直接被计算机使用。相反，我们每秒多次测量（或采样）波的振幅，然后量化该振幅，将其四舍五入到最接近的可表示值。

这种声音的表示 - 一个长的、均匀采样的振幅列表被称为脉冲编码调制 (PCM)。 PCM 可以被认为是“标准”音频格式，因为它非常容易使用。例如，要将两段音频混合在一起，您只需将两个轨道的样本添加在一起并取平均值即可。

CC：Tweaked 的扬声器也支持 PCM 音频。它每秒回放 48,000 个样本，其中每个样本都是 -128 到 127 之间的整数。这通常称为 48kHz 和 8 位分辨率。

现在让我们看一个简单的例子。我们将生成 220Hz 的 正弦波，这听起来像低沉单调的嗡嗡声。首先，我们包装扬声器外设，然后用 128×1024 个样本填充一个表（也称为 缓冲区 ）——这是扬声器一次可以接受的最大样本数。

为了填充这个缓冲区，我们需要做一些数学计算。我们希望每秒播放 220 个正弦波，其中每个正弦波以 2π“单位”完成一次完整振荡。这意味着一秒的音频长度为 2×π×220 个“单位”。然后，我们需要将其分成 48k 个样本，基本上意味着对于每个样本，我们“沿着”正弦曲线移动 2×π×220/48k。

local speaker = peripheral.find("speaker")

local buffer = {}
local t, dt = 0, 2 * math.pi * 220 / 48000
for i = 1, 128 * 1024 do
    buffer[i] = math.floor(math.sin(t) * 127)
    t = (t + dt) % (math.pi * 2)
end

speaker.playAudio(buffer)

流媒体音频

您可能会注意到，上面的代码片段仅生成一小段音频 - 略多于 2.7 秒。虽然我们可以尝试增加循环迭代的次数，但当我们尝试通过扬声器播放它时，我们会收到错误：声音缓冲区太大而无法处理。

我们的 2.7 秒音频存储在一个包含超过 130 千 个元素的表中。如果我们想播放一整分钟的正弦波（你为什么不呢？），你需要一张有近 3 百万 的桌子。突然你发现这些数字加起来很快，而且这些表占用的内存越来越多。

我们不必一次性构建整首歌曲（嗯，正弦波），而是可以小批量地制作它，在适当的时候将每首歌曲传递给 speaker.playAudio。这使我们能够构建音频的 流，在其中我们一次读取一个音频块（从文件或如上所述的音频发生器），对每个音频块进行一些可选处理，然后播放它们。

让我们调整上面的示例来做到这一点。

local speaker = peripheral.find("speaker")

local t, dt = 0, 2 * math.pi * 220 / 48000
while true do
    local buffer = {}
    for i = 1, 16 * 1024 * 8 do
        buffer[i] = math.floor(math.sin(t) * 127)
        t = (t + dt) % (math.pi * 2)
    end

    while not speaker.playAudio(buffer) do
        os.pullEvent("speaker_audio_empty")
    end
end

它看起来与之前非常相似，除了我们将生成和播放代码包装在 while 循环中，并添加了一个带有 speaker.playAudio 和 os.pullEvent 的相当奇怪的循环。

我们来说说这个循环，为什么要一直调用speaker.playAudio呢？请记住，我们在这里尝试做的是避免在内存中同时保留太多音频。但是，如果我们生成音频的速度比扬声器播放它的速度快，那么我们根本没有帮助 - 所有这些音频仍然挂在等待播放！

为了避免这种情况，如果积压的音频太大，扬声器将拒绝任何新的音频块。发生这种情况时，speaker.playAudio 返回 false。一旦播放了足够的音频，并且积压已减少，speaker_audio_empty 事件就会排队，我们可以尝试再次播放我们的块。

存储音频

当我们想要操作音频时，PCM 是一种很棒的表示音频的方式，但是当我们想要将其存储到磁盘时，它的效率不是很高。将 WAV 文件（使用 PCM）的大小与同等 MP3 的大小进行比较，通常是其大小的 5 倍。相反，我们以特殊格式（或 编解码器）存储音频，然后在需要对其进行处理时将它们转换为 PCM。

现代音频编解码器使用一些令人难以置信的令人印象深刻的技术来尽可能地压缩音频，同时保持音质。然而，由于 CC: Tweaked 的处理能力有限，实际上不可能从您的计算机上使用这些。相反，我们需要一些更简单的东西。

DFPWM（动态滤波器脉冲宽度调制）是 ComputerCraft（和 OpenComputers）世界事实上的标准音频格式。 CC:T 最初由附加模块 Computronics 普及，现在通过 cc.audio.dfpwm 模块对其提供内置支持。这允许您从磁盘读取 DFPWM 文件，将其解码为 PCM，然后使用扬声器播放它们。

让我们深入了解一个示例，然后我们将进行解释：

local dfpwm = require("cc.audio.dfpwm")
local speaker = peripheral.find("speaker")

local decoder = dfpwm.make_decoder()
for chunk in io.lines("data/example.dfpwm", 16 * 1024) do
    local buffer = decoder(chunk)

    while not speaker.playAudio(buffer) do
        os.pullEvent("speaker_audio_empty")
    end
end

我们再次看到 speaker.playAudio/speaker_audio_empty 循环。然而，该计划的其余部分有点不同。

首先，我们需要 DFPWM 模块并调用 cc.audio.dfpwm.make_decoder 构建一个新的解码器。该解码器接受 DFPWM 数据块并将其转换为 8 位幅度列表，然后我们可以用扬声器播放该列表。

如上所述，speaker.playAudio一次性最多接受128×1024个样本。 DFPWM 对每个样本使用一位，这意味着我们希望以 16×1024 字节 (16KiB) 的块来处理音频。为了做到这一点，我们使用 io.lines，它提供了一种循环文件块的好方法。如果您愿意，当然可以只使用 fs.open 和 fs.ReadHandle.read 。

处理音频

正如本指南开头附近提到的，PCM 音频非常容易使用，因为它只是一个幅度列表。您可以通过添加振幅来将不同流中的样本混合在一起，通过删除样本来更改播放速率等...

让我们在这里做一个小演示。我们将为上面的歌曲添加一个小的延迟效果，以便您在一秒半后听到微弱的回声。

为了做到这一点，我们将遵循与前面的示例类似的格式，解码音频然后播放它。然而，我们还将在这两个步骤之间添加一些新的逻辑，循环遍历音频块中的每个样本，并将 1.5 秒前的样本添加到其中。

为此，我们需要跟踪最后 72k 个样本 - 正好相当于 1.5 秒的音频。我们可以使用 Ring Buffer 来做到这一点，这有助于提高效率。

local dfpwm = require("cc.audio.dfpwm")
local speaker = peripheral.find("speaker")

-- Speakers play at 48kHz, so 1.5 seconds is 72k samples. We first fill our buffer
-- with 0s, as there's nothing to echo at the start of the track!
local samples_i, samples_n = 1, 48000 * 1.5
local samples = {}
for i = 1, samples_n do samples[i] = 0 end

local decoder = dfpwm.make_decoder()
for chunk in io.lines("data/example.dfpwm", 16 * 1024) do
    local buffer = decoder(chunk)

    for i = 1, #buffer do
        local original_value = buffer[i]

        -- Replace this sample with its current amplitude plus the amplitude from 1.5 seconds ago.
        -- We scale both to ensure the resulting value is still between -128 and 127.
        buffer[i] = original_value * 0.6 + samples[samples_i] * 0.4

        -- Now store the current sample, and move the "head" of our ring buffer forward one place.
        samples[samples_i] = original_value
        samples_i = samples_i + 1
        if samples_i > samples_n then samples_i = 1 end
    end

    while not speaker.playAudio(buffer) do
        os.pullEvent("speaker_audio_empty")
    end

    -- The audio processing above can be quite slow and preparing the first batch of audio
    -- may timeout the computer. We sleep to avoid this.
    -- There's definitely better ways of handling this - this is just an example!
    sleep(0.05)
end
