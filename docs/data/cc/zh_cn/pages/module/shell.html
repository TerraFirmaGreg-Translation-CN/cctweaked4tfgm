shell

shell API 提供对 CraftOS 命令行界面的访问。

它允许你 启动程序、为程序添加补全，以及更多。

shell 不是“真正”的 API。相反，它是一个标准程序，会将其 API 注入到它启动的程序中。这允许多个 shell 同时运行，但意味着该 API 在全局环境中不可用，因此其他 API 也无法使用它。

程序与程序路径

当你在 shell 中运行命令时，无论是从提示符还是 从 Lua 代码，shell API 都会执行几个步骤来确定要运行哪个程序：

  1. 首先，shell 会尝试解析 别名。这允许我们为单个命令使用多个名称。例如，list 程序有两个别名：ls 和 dir。当你输入 ls /rom 时，它会被展开为 list /rom。

  2. 接下来，shell 会尝试找到程序实际所在的位置。为此，它使用 程序路径。这是一个以冒号分隔的目录列表，会检查其中每个目录是否包含该程序。

    list 或 list.lua 不存在于 .（当前目录）中，因此 shell 现在会查看 /rom/programs，在那里可以找到 list.lua！

  3. 最后，shell 会读取文件并检查文件是否以 #! 开头。这是一个 hashbang，表示此文件不应被视为 Lua，而是应传递给 另一个 程序，其名称应跟在 #! 之后。

execute(command, ...)Source

使用提供的参数运行程序。

与 shell.run 不同，每个参数都会原样传递给程序。shell.run("echo", "b c") 运行 echo，并传入 b 和 c，而 shell.execute("echo", "b c") 运行 echo，并传入单个参数 b c。

参数

  1. command string 要执行的程序。
  2. ... string 此程序的参数。

返回值

  1. boolean 程序是否成功退出。

用法

  • 在程序内部运行 paint my-image：

    shell.execute("paint", "my-image")

变更记录

  • 1.88.0 版本新增
run(...)Source

使用提供的参数运行程序。

所有参数会拼接在一起，然后作为命令行解析。因此，shell.run("program a b") 等同于 shell.run("program", "a", "b")。

参数

  1. ... string 要运行的程序及其参数。

返回值

  1. boolean 程序是否成功退出。

用法

  • 在程序内部运行 paint my-image：

    shell.run("paint", "my-image")

另见

  • shell.execute 直接运行程序，不解析参数。

变更记录

  • 在版本 1.80pr1 中变更： 程序现在拥有自己的环境，而不是共享同一个环境。
  • 在版本 1.83.0 中变更： arg 现在会被添加到环境中。
exit()Source

退出当前命令行。

这不会终止你的程序，它只是让命令行在你的程序结束后终止。如果这是顶层命令行，那么计算机将会关机。

path()Source

获取程序所在的路径。

该路径由字符串中的一组目录名组成，每个目录名用冒号（:）分隔。在普通海龟上，会查看当前目录（.）、/rom/programs 和 /rom/programs/turtle 文件夹，从而构成路径 .:/rom/programs:/rom/programs/turtle。

返回值

  1. string 当前命令行的路径。

另见

  • setPath 用于更改当前路径。
setPath(path)Source

设置当前程序路径。

请务必在目录前加上 /。否则将从当前目录而不是计算机根目录中搜索它们。

参数

  1. path string 新的程序路径。

变更

resolve(path)Source

将相对路径解析为绝对路径。

fs 和 io API 使用绝对路径，因此我们必须把相对于当前目录的任何路径转换为绝对路径。当路径以 / 开头时，此操作不执行任何操作。

参数

  1. path string 要解析的路径。

用法

  • 解析 startup.lua（当位于 rom 文件夹中时）。

    shell.setDir("rom")
print(shell.resolve("startup.lua"))
-- => rom/startup.lua

参数

  1. command string 程序的名称

返回值

  1. string | nil 程序的绝对路径；如果找不到，则为 nil。

用法

  • 定位 hello 程序。

 -- => rom/programs/fun/hello.lua

complete(sLine)Source

补全命令行。

它接受不完整的命令，并补全程序名或参数。例如，l 将被补全为 ls，而 ls ro 将被补全为 ls rom/。

你的程序的补全处理函数可以通过 shell.setCompletionFunction 注册。

参数

  1. sLine string 要补全的输入。

返回值

  1. { string } | nil 可能的补全项列表。

另请参阅

  • _G.read 有关补全的更多信息。
  • shell.completeProgram
  • shell.setCompletionFunction
  • shell.getCompletionInfo

变更

setCompletionFunction(program, complete)Source

设置程序的补全函数。当在命令行中输入该程序时，将调用此程序以提供自动补全信息。

补全函数接受四个参数：

  1. 当前命令行。由于补全函数会被继承，因此不能保证这是你注册此函数时所在的命令行。
  2. 当前正在补全的参数的索引。
  3. 当前参数。这可能是空字符串。
  4. 先前参数的列表。

例如，当补全 pastebin put rom/st 时，我们的 pastebin 补全函数将收到 shell API、索引 2、作为当前参数的 rom/st，以及包含 { "put" } 的“previous”表。此函数随后可能希望返回一个包含 artup.lua 的表，表示整个命令应补全为 pastebin put rom/startup.lua。

你的补全项后面也可以跟一个空格，如果你想表示还期望另一个参数。

参数

  1. program string 程序的路径。这应当是一个绝对路径，不带开头的 /。
  2. complete function(shell: table, index: number, argument: string, previous: { string }):{ string } | nil 补全函数。

另请参阅

  • cc.shell.completion 各种有助于编写补全函数的实用工具。
  • shell.complete
  • _G.read 有关补全的更多信息。

变更

  • 新增于版本 1.74

aliases()Source

获取此命令行的当前别名。

别名用于允许多个命令引用单个程序。例如，list 程序被别名为 dir 或 ls。在命令行中运行 ls、dir 或 list 都将运行 list 程序。

返回值

  1. { [string] = string } 一个表，其中键是别名的名称，值是程序的路径。

另请参阅

  • shell.setAlias
  • shell.resolveProgram 在将程序名解析为绝对路径时使用别名。
openTab(...)Source

打开一个运行命令的新 multishell 标签页。

其行为类似于 shell.run，但返回的是进程索引。

仅当 multishell API 可用时，此函数才可用。

参数

  1. ... string 要运行的命令行。

返回值

  1. number 已打开的新标签页的 ID。

用法

  • 启动 Lua 解释器并切换到它。

    local id = shell.openTab("lua")
shell.switchTab(id)

另见

  • shell.run
  • multishell.launch

变更

  • 1.6 版本新增
