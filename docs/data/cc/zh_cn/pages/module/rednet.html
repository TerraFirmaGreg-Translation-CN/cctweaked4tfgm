rednet

通过使用 调制解调器 与其他计算机通信。rednet 在主 modem 外设之上提供了一层抽象，使其使用起来稍微更容易。

基本用法

为了在两台计算机之间发送消息，每台计算机的某一侧都必须有一个调制解调器（对于便携式计算机和海龟，调制解调器必须作为升级装备）。然后两台计算机应调用 rednet.open，这会让调制解调器准备好发送和接收消息。

一旦 rednet 被打开，你就可以使用 rednet.send 发送消息，并使用 rednet.receive 接收消息。也可以向每一台使用 rednet 的计算机通过 rednet.broadcast 发送消息。

⚠ 网络安全

虽然 rednet 提供了一种向特定计算机发送消息的友好方式，但它不提供任何安全性保证。其他计算机可能会监听你的消息，甚至假装从其他计算机发送消息！

如果你在多玩家服务器上游戏（或者至少是在你不信任其他玩家的服务器上），那么值得对 rednet 消息进行加密或签名。

协议与主机名

一些 rednet 消息接受“protocol”（协议）——描述消息内容的简单字符串名称。使用 rednet.send 和 rednet.broadcast 发送消息时，你可以选择为消息指定一个协议。然后可以将同一协议传给 rednet.receive，以忽略所有不使用此协议的消息。

还可以基于协议查找计算机，提供服务发现和 DNS 的基本系统。计算机可以通过 rednet.host 宣告自己支持某个特定协议，同时提供一个友好的“hostname”（主机名）。其他计算机随后可以使用 rednet.lookup 找到所有支持此协议的计算机。

  • modem Rednet 构建在调制解调器外设之上。调制解调器提供更基础但更灵活的接口。

open(modem)Source

打开具有给定 peripheral 名称的调制解调器，使其可以通过 rednet 发送和接收消息。

这将在两个频道上打开调制解调器：一个与计算机具有相同的 ID，另一个在 广播频道 上。

参数

  1. modem string 要打开的调制解调器的名称。

抛出

  • 如果没有具有给定名称的此类调制解调器

用法

  • 在计算机背面打开 rednet，使你可以使用它发送和接收 rednet 消息。

    rednet.open("back")

  • 在所有连接的调制解调器上打开 rednet。这会滥用 peripheral.find 的“filter”参数。

    peripheral.find("modem", rednet.open)

另见

  • rednet.close
  • rednet.isOpen
close([modem])Source

关闭具有给定 peripheral 名称的调制解调器，这意味着它不能再发送和接收 rednet 消息。

参数

  1. modem? string 调制解调器所在的一侧。如果未给出，将关闭所有已打开的调制解调器。

抛出

  • 如果没有具有给定名称的此类调制解调器

另见

  • rednet.open
isOpen([modem])Source

确定 rednet 当前是否已打开。

参数

  1. modem? string 要检查哪个调制解调器。如果未给出，将检查所有连接的调制解调器。

返回

  1. boolean 给定调制解调器是否已打开。

另见

  • rednet.open

send(recipient, message [, protocol])Source

允许带有附加调制解调器的计算机或海龟向具有特定 ID 的计算机发送消息。必须先打开至少一个此类调制解调器，然后才能发送。

假设目标在范围内并且也正确打开了调制解调器，目标计算机随后可以使用 rednet.receive 来接收该消息。

参数

  1. recipient number 接收计算机的 ID。
  2. message 要发送的消息。与 modem.transmit 一样，它可以包含任何原始类型（数字、布尔值和字符串）以及表。其他类型（如函数）以及元表将不会被传输。
  3. protocol? string 发送此消息所用的“protocol”。使用 rednet.receive 时，可以过滤为只接收在特定 protocol 下发送的消息。

返回

  1. boolean 此消息是否已成功发送（即 rednet 当前是否已打开）。注意，这并不保证消息实际上已被接收。

用法

  • 向计算机 #2 发送一条消息。

    rednet.send(2, "Hello from rednet!")

另见

  • rednet.receive

更改

  • 在版本 1.6 中更改： 添加了 protocol 参数。
  • 在版本 1.82.0 中更改： 现在返回消息是否已成功发送。
broadcast(message [, protocol])Source

在预定义的 CHANNEL_BROADCAST 频道上广播字符串消息。每个监听 rednet 的设备都会收到该消息。

参数

  1. message 要发送的消息。它不应包含协程或函数，因为它们会被转换为 nil。
  2. protocol? string 发送此消息所用的“protocol”。使用 rednet.receive 时，可以过滤为只接收在特定 protocol 下发送的消息。

用法

  • 向使用 rednet 的每台计算机广播“Hello, world!”。

    rednet.broadcast("Hello, world!")

另见

  • rednet.receive

更改

  • 在版本 1.6 中更改： 添加了 protocol 参数。
receive([protocol_filter [, timeout]])Source

等待接收 rednet 消息，或直到经过 timeout 秒。

参数

  1. protocol_filter? string 接收到的消息必须使用的 protocol。如果指定，则所有未在此 protocol 下发送的消息都将被丢弃。
  2. timeout? number 未收到消息时等待的秒数。

返回

  1. number 发送此消息的计算机
  2. 接收到的消息
  3. string | nil 此消息发送时所用的 protocol。

或

  1. nil 如果超时且未收到任何消息。

用法

  • 接收一条 rednet 消息。

    local id, message = rednet.receive()
print(("Computer %d sent message %s"):format(id, message))

  • 接收一条消息；如果未收到消息，则在 5 秒后停止。

    local id, message = rednet.receive(nil, 5)
if not id then
    printError("No message received")
else
    print(("Computer %d sent message %s"):format(id, message))
end

  • 从计算机 #2 接收一条消息。

    local id, message
repeat
    id, message = rednet.receive()
until id == 2

print(message)

另见

  • rednet.broadcast
  • rednet.send

更改

  • 在版本 1.6 中更改： 添加了 protocol 过滤参数。
host(protocol, hostname)Source

将系统注册为在指定名称下“托管”所需的协议。如果在同一网络上对该协议（可能还有名称）执行 rednet 查找，已注册的系统将通过后台进程自动响应，从而向执行查找的系统提供其 ID 号。

多台计算机不能在同一网络上针对相同协议注册相同的名称，并且标题 localhost 是专门保留的。但是，只要它们托管的协议不同，或者它们先“注册”自己然后再加入给定网络（例如在离线时或作为另一个网络的一部分时），它们就可以共享名称。

参数

  1. protocol string 此计算机提供的协议。
  2. hostname string 此计算机为给定协议公开的名称。

抛出

  • 如果尝试注册的主机名已被保留或当前正在使用。

另见

  • rednet.unhost
  • rednet.lookup

更改

  • 1.6 版本新增
unhost(protocol)Source

停止托管特定协议，这意味着它将不再响应 rednet.lookup 请求。

参数

  1. protocol string 要从中注销自身的协议。

lookup(protocol [, hostname [, timeout=2]])Source

在本地 rednet 网络中搜索托管所需协议的系统，并返回任何针对该协议以“registered”响应的计算机 ID。

如果指定了主机名，则只会返回一个 ID（假设找到完全匹配项）。

参数

  1. protocol string 要搜索的协议。
  2. hostname? string 要搜索的主机名。
  3. timeout? number = 2 等待查找响应的秒数。

返回

  1. number... 托管给定协议的计算机 ID 列表。

或

  1. number | nil 具有所提供主机名和协议的计算机 ID，如果不存在则为 nil。

用法

  • 查找所有正在托管 "chat" 协议的计算机。

    local computers = {rednet.lookup("chat")}
print(#computers .. " computers available to chat")
for _, computer in pairs(computers) do
  print("Computer #" .. computer)
end

  • 查找一台托管 "chat" 协议且主机名为 "my_host" 的计算机。

    local id = rednet.lookup("chat", "my_host")
if id then
  print("Found my_host at computer #" .. id)
else
  printError("Cannot find my_host")
end

变更

  • 1.6 版本新增
  • 在版本 1.118.0 中变更： 添加了 timeout 参数。
run()Source

监听调制解调器消息并将其转换为 rednet 消息，之后这些消息可被接收。

此功能会在计算机启动时自动在后台启动，不应手动调用。
